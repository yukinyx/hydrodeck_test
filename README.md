## ESP-NOW and Connectivity Notes

The firmware targets Espressif Arduino core 3.3.12 and its ESP-IDF 5.x ESP-NOW API (`esp_now_recv_info_t` receive callback). MAIN keeps AP+STA mode; its provisioning AP follows the home router's channel while STA is connected. ESP-NOW peers use channel 0, meaning the current radio channel. RAIN does not associate with MAIN's hotspot or home Wi-Fi. Without an authenticated MAIN beacon, it hops channels 1 through 13 on a 450 ms timer and listens while servicing its local safety loop; no blocking Wi-Fi scan is used. After a valid beacon, it pairs on that channel and broadcasts a hello so MAIN can learn RAIN's MAC. A missed MAIN heartbeat turns pumps OFF and resumes hopping; ESP-NOW initialization failures are retried independently. The channel range must be narrowed to locally permitted 2.4 GHz channels when required. Discovery can take multiple sweeps. This is not channel-independent: one ESP32 radio cannot exchange ESP-NOW across channels at the same time.

ESP-NOW packets are packed fixed-size structures with a common header: magic `0x4859`, protocol version `2`, message type, sender identity, payload size, and sequence. CRC-16 covers bytes before its field; the 8-byte HMAC-SHA256 tag covers the populated packet through the CRC. Both are finalized after payload fields are set. MAIN beacon and pump-command sequence windows are tracked independently on RAIN so beacon traffic cannot invalidate a valid command. Message types are RAIN hello/status, MAIN beacon, pump command, and command ACK. Status contains RAIN boot ID, uptime, channel, the single reservoir full flag, pump mask, active command, and fault. Commands contain MAIN boot ID, command ID, pump, desired state, and remaining runtime. ACKs echo the command ID and include accepted, duplicate, or rejected plus a reason. The broadcast hello is authenticated by HMAC; paired unicast peers use ESP-NOW encryption.

MAIN retries an unacknowledged command every 250 ms using the same command ID. RAIN acknowledges a duplicate without toggling the relay or restarting a run. Water-pump commands have no runtime deadline; RAIN turns both relays OFF on boot, requires a fresh OFF command after boot or a 3-second MAIN heartbeat loss before accepting a new ON, and has its local runtime cap disabled (`LOCAL_MAX_RUN_MS = 0`). Water pumps remain ON until an OFF command. Chemical-pump pulses and automatic pH dosing remain on MAIN. RAIN GPIOs are waterPump1 GPIO 25, waterPump2 GPIO 12, and the shared reservoir float GPIO 21 (`INPUT_PULLUP`, HIGH=full). Relay polarity remains ON=HIGH, OFF=LOW. GPIO 12 is a strapping pin and its relay input must not pull high during boot.

Home shows one reachability label: `Connected locally` for fresh local MAIN telemetry, `Online` for a fresh MAIN Firebase heartbeat when local telemetry is stale, and `ESP32 offline` otherwise. RAIN's ESP-NOW heartbeat remains separate internally for pump safety and reservoir availability. Serial logs report Wi-Fi disconnect reasons, connected RSSI/channel, Firebase readiness/heartbeat age, ESP-NOW discovery attempts/active channel/peer changes/queue drops/retries/ACKs, and reservoir transitions. These logs can identify code-level timeout or authentication failures; they cannot establish physical causes such as router behavior, power, antenna placement, radio interference, pump timing, or radio range.

The sketches currently contain embedded Wi-Fi/Firebase credentials and the shared RAIN pairing token. They are not repeated here or printed by diagnostics. No existing ignored local secrets-header/build configuration was found, so the values were not removed in a way that would break Arduino builds. Rotate the Firebase device credential and RAIN token before deployment. A safe extraction requires adding a local-only secrets header, adding it to `.gitignore`, providing a non-secret example header, and verifying that both Arduino sketches compile with that local header present before removing the current definitions.
